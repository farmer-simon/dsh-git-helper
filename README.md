# dsh-git-helper · DSH Git 助手

一个装在 DeepSeek Harness（DSH）对话框里的 Git 助手：在输入框旁直接查看当前项目的分支状态，并完成切换/新建/合并分支、由模型按 Conventional Commits 生成中文说明后提交、推送、初始化仓库等日常操作，不用切到终端。

## 功能一览

| 功能 | 说明 |
| --- | --- |
| 查看状态 | 显示当前分支、工作区是否有未提交变更；面板内还有仓库名、上游跟踪（如 `origin/main`）、领先/落后提交数、最近一次提交 |
| 切换分支 | 列出本地分支，点击即切换到该分支（`git checkout <分支>`） |
| 新建分支 | 输入分支名，可指定起点（默认当前 HEAD），创建后自动切过去（`git checkout -b`） |
| 合并分支 | 把选中的本地分支合并进当前分支（`git merge --no-edit`） |
| 提交 | 由模型根据实际改动按 Conventional Commits 生成中文提交说明，可编辑/重新生成后提交；模型不可用时回退为文件级摘要（`git add -A` + `git commit`） |
| 推送 | 有上游时 `git push`；没有上游时自动 `git push -u <remote> <当前分支>` |
| 初始化仓库 | 项目不是 Git 仓库时，一键 `git init`（新仓库默认分支为 `main`） |

## 在哪里看到它

DSH Web 界面的输入框左下角工具行（权限选择器旁边）会出现一个分支标签：

```
⑂ main          ← 默认显示当前分支
⑂ feature/x  ●  ← ● 表示有未提交的变更
```

- 点击标签打开面板；点击面板外或按 `Esc` 关闭。
- 面板每 15 秒自动刷新一次（页面可见时），点开面板、执行任何操作后也会刷新。
- 当前项目不是 Git 仓库时，标签显示「初始化 Git」，点开后可一键初始化。
- 处于 detached HEAD（游离头指针）时，标签显示 `detached HEAD`，仍然可以切换/新建分支，但不能合并或推送。
- 如果当前会话没有可用的项目目录或 Git 服务异常，标签会显示 `Git`，点开后显示具体原因和「刷新」按钮。

> 这里的「当前项目」指当前会话打开的工作目录。若会话是从仓库子目录打开的，状态和提交仍以该目录所属的整个仓库为单位。

## 使用说明

### 切换、新建、合并分支

- **切换**：面板「切换分支」区域列出所有本地分支，当前分支带勾选标记，点击其他分支即可切换。工作区有冲突性改动时 Git 会拒绝切换，错误会直接显示在面板里。
- **新建**：选「新建分支…」，填写分支名（会校验合法性，重名会被拒绝），可选起点分支；创建成功后自动切换到新分支。
- **合并**：选「合并分支…」，选择一个本地分支合并到当前分支。若产生冲突，面板会提示冲突，工作区保留冲突状态；请到终端解决冲突（或执行 `git merge --abort` 放弃）后回来继续。

### 提交

点击「提交变更…」后，面板会先展示本次要提交的文件清单和由模型生成的提交说明（并标明所用模型），你可以修改文字或点「重新生成」，确认后点「确认提交」。提交执行的是：

```
git add -A
git commit -m <说明主题> -m <说明正文>
```

- 工作区没有变更时会直接提示，不会产生空提交。
- 存在未解决的合并冲突时会拒绝提交（避免把冲突标记 `<<<<<<<` 之类提交进去），并提示先解决冲突或 `git merge --abort`。
- `git add -A` 会暂存整个仓库的当前变更，一次提交全部改动。
- 模型不可用或生成内容不合规时，面板会说明原因并给出文件级摘要，不会阻止提交。

### 推送

- 工作区有未提交变更时会拒绝推送，先提交或清理后再推。
- 没有配置上游分支时，自动使用 `origin`（没有 `origin` 时用第一个远程仓库）并设置上游。
- 没有配置任何远程仓库、处于 detached HEAD、或推送需要交互式输入凭据时会失败，并把 Git 的原始错误显示在面板中。

### 初始化仓库

标签显示「初始化 Git」时，点开面板并确认即可执行 `git init`（较新版本的 Git 会把初始分支命名为 `main`）。初始化后即可正常使用其余功能。

## 提交说明是怎么生成的

### 默认：模型分析改动后生成

点击「提交变更…」或「重新生成」时，Host 会把以下内容发给**当前会话正在使用的大模型**，要求生成一条中文 Conventional Commits 提交信息：

- `git status` 的变更清单；
- `git diff HEAD` 的差异（最多约 16000 个字符，超出会截断并注明）；
- 未跟踪新文件的内容预览（最多 10 个文件、每个前 40 行；超过 512 KB 或二进制文件跳过）。

提示词要求：类型只能是 `feat` / `fix` / `docs` / `refactor` / `test` / `chore`；首行为 `类型(可选范围): 概要`；概要不超过 50 个汉字；只能描述真实存在的改动，不得编造。模型返回后还会做格式校验，不合法就不会被采用。请求超时时间为 45 秒。

生成后，面板会标明「由 <供应商/模型> 生成」，你可以直接修改，或点「重新生成」再试一次。

> **隐私说明**：只有点击「提交变更…」或「重新生成」时才会发送上述内容；打开面板、切换分支、查看状态等操作不会发送。发送的是截断后的改动片段，不是整个仓库。如果不想让代码离开本机，请不要使用该按钮，手动填写说明即可。

### 回退：本地文件级摘要

模型服务不可用、请求超时、当前会话没有可用模型，或模型输出不符合 Conventional Commits 格式时，插件会说明原因，并回退到本地生成的摘要（没有类型前缀，建议手动补上）：

- **主题**：按变更类型和数量生成，并带上涉及的顶层目录（文件都在仓库根目录时不附加目录），例如：
  - `新增 3 个文件：src`
  - `修改 2 个文件：lib、test`
  - `更新 5 个文件（新增 1 / 修改 3 / 删除 1）：src、docs`

  主题超过 72 个字符时会截断。
- **正文**：逐文件列出变更类型、路径和行数增减，例如：

  ```
  修改 src/index.js  (+12 / -3)
  新增 docs/usage.md  (+40 / -0)
  删除 legacy/old.js  (+0 / -18)
  ```

  最多列出 40 个文件，超过时以「… 另有 N 个文件」收尾。
- **行数来源**：已跟踪文件来自 `git diff --numstat`；未跟踪的文本文件按本地内容统计（超过 2 MB 或二进制文件不计行数）；重命名/复制条目只列路径、不列行数。
- 结尾固定附一行「由 DSH Git 助手自动总结生成」；整个说明都可以在提交前编辑。

## 安装

要求：已安装 DSH（在 0.2.1-rc.3 的 Web / Desktop Web UI 上验证），并且运行 DSH 的机器上已安装 Git。使用模型生成提交说明时，还需要当前会话已配置可用的模型（不可用时自动回退）。

把插件目录（或 `npm pack` 生成的 `.tgz`）放到目标机器上，然后任选一种方式安装：

- 打开 DSH 的**插件管理页**，在添加入口中填入插件目录的绝对路径或 `.tgz` 路径；
- 或使用命令行：

  ```bash
  dsh plugin add "D:/path/to/dsh-git-helper"
  ```

安装完成后刷新 DSH 页面（必要时重启 DSH），输入框左下角就会出现分支标签。卸载时在插件管理页移除即可，不会改动你的仓库。

> 本插件以本地链接方式安装时，移动或重命名插件目录会导致链接失效；需要迁移时请先移除插件，再从新位置重新安装。

## 实现与安全

- 插件分两半：Host 半负责执行 Git 操作，Client 半负责输入框旁的界面。
- Host 半注册一个同源 JSON 接口 `POST /dsh-git-helper/api`，请求必须通过 DSH 自身的来源与登录校验（`connection.requestRejection()`），未登录/不受信任的请求会被拒绝；随后按请求中的会话 ID 解析当前项目目录并在该目录执行 Git。同一目录的写操作会串行执行，Git 调用有 60 秒超时，并禁用交互式凭据提示，避免请求挂死。
- Client 半是普通 JavaScript 模块，只通过页面的同源 `fetch` 调用上述接口；界面样式全部使用 DSH 主题变量，自动适配明暗主题和中英文界面。
- 插件没有第三方运行时依赖，不收集/上传任何数据。除 `git push` 与生成提交说明时的模型请求外，不主动访问网络：模型请求只在你点击「提交变更…」或「重新生成」时发出，内容是截断后的改动片段，发给当前会话使用的模型服务。Git 命令以参数数组方式调用（不经过 shell），不存在命令拼接注入。
- 所有写操作（提交、推送、切换/新建/合并分支、初始化）都需要你在面板里明确点击，插件不会在后台自动提交或推送。
- 由于插件会以你的 Git 凭据执行提交/推送，请只从可信来源安装，或直接审阅 `index.js` / `client.js`。

## 测试与开发

```bash
node --check index.js        # Host 半语法检查
node --check client.js       # Client 半语法检查
node test/host.test.mjs      # Host 半集成测试
```

测试会在系统临时目录创建一次性 Git 仓库（不触碰当前项目），覆盖仓库探测、状态解析（含重命名/游离 HEAD）、提交说明生成、提交、创建/切换/合并分支、推送与上游设置、初始化仓库、合并冲突拦截、未跟踪文件行数统计，以及模型说明的格式校验与三种回退路径等 21 项检查；模型调用使用测试桩，不访问网络。

开发时的生效方式：修改 `client.js` 后刷新页面；修改 `index.js` 后重启 DSH（或由 HMR 自动重载）。

目录结构：

| 文件 | 作用 |
| --- | --- |
| `index.js` | Host 半：鉴权接口、状态解析、Git 操作、提交说明生成 |
| `client.js` | Client 半：输入框旁的分支标签与操作面板 |
| `cordis.patch.yml` | 插件在 DSH profile 中的注册补丁 |
| `locale/*.json` | 插件在插件管理页显示的中英文名称与描述 |
| `icon.svg` | 插件图标 |
| `test/host.test.mjs` | Host 半集成测试 |

## 常见问题

**输入框旁没有出现分支标签？**
先刷新页面；确认插件在插件管理页中已启用；确认当前会话已打开一个存在的项目目录。旧版 DSH 的输入框工具行可能没有这个位置，请升级到 0.2.x。

**点击后提示「Git 服务未就绪」或「需要先登录 DSH 页面」？**
说明 Host 半未加载或页面登录态已失效。先刷新/重新打开 DSH 页面；仍未恢复时重启 DSH。

**为什么显示「初始化 Git」？**
当前项目目录还不是 Git 仓库。点击后确认初始化即可。

**推送失败，提示需要凭据或超时？**
本插件不处理交互式登录。请先在终端里对该仓库执行一次成功的 `git push`（配置好凭据/SSH），或确保凭据助手可用后重试。注意工作区有未提交变更时也会拒绝推送。

**合并冲突之后怎么办？**
到终端解决冲突并 `git add`/`git commit`，或执行 `git merge --abort` 放弃合并，然后回到面板刷新状态。本插件不提供冲突解决界面。

## 已知限制

- 只针对当前机器上的本地 Git 仓库；远程/SSH 工作区不保证可用。
- 提交说明由模型生成，需要当前会话有可用模型；模型不可用、超时或输出不合规时会回退为文件级摘要，不会自动补类型前缀。
- 使用模型生成说明时，截断后的改动片段会发送给当前会话的模型服务（见「提交说明是怎么生成的」中的隐私说明）。
- 不提供 stash、rebase、tag、amend、撤销提交、丢弃改动、冲突解决、历史浏览等高级操作。
- 暂无可配置项（如自动推送策略、提交说明模板等）。
- 不支持同一面板同时管理多个仓库；切换仓库请切换会话。
